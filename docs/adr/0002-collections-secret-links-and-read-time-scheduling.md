# One Collection model, secret links instead of unlisted, scheduling evaluated at read time

`Release` and `Playlist` become a single `Collection` with a type (`PLAYLIST`, `ALBUM`, `EP`, `SINGLE`, `COMPILATION`); the type decides presentation, not membership. `Visibility` is `PUBLIC | PRIVATE | SCHEDULED` (collections cannot be scheduled) and the old `UNLISTED` state is replaced by private content plus a per-item secret token in the URL (`/…/s-{token}`, resettable). Scheduled tracks are never flipped by a job: `effectiveVisibility(entity, now)` and the shared Prisma `where` builders decide at read time, because Vercel Hobby crons run at most daily. Every surface (listings, search, feed, route handlers) uses `server/modules/visibility`; hand-written visibility conditions are not allowed.

Why: it mirrors the SoundCloud model the product is specified against (PRD 0.1, 7.7), removes a duplicated schema and duplicated UI for two ways of ordering tracks, and makes "who can see what" a single reviewed function with a test per surface. The cost is that access needs the viewer, the secret and sometimes a collection secret, so route handlers answer 404 (never 403) after `authorizeTrack(...)`.

Also decided with it: permalink routing by lowercase usernames and per-owner slugs with redirect tables for renames; denormalised counters change only with real row changes in the same transaction (`pnpm db:recount` repairs them); R2 deletions go through a durable queue (`StorageDeletion`) drained by `after()` and the daily cron; the audio asset of a track may be shared by several tracks (demo data), so asset deletion never assumes a single owner track.
